# Architecture

## Product boundary

The runtime is a durable shell around interchangeable reasoning kernels. A distribution supplies optional identity and interaction policy; profile-scoped roots supply selected skills; tenant evidence supplies personal context. A channel only translates transport payloads. A provider only translates model calls. Memory is owned by the user-facing runtime and can move between both. The neutral distribution is the default, unknown distributions fail closed, and bundled manifests are data rather than branches in runtime code.

Every model role has an independently release-pinned route, output limit, reasoning effort, and optional API request-cost envelope. The envelope contains operator-supplied input/output prices and a per-request ceiling; the runtime never embeds a price table that will silently go stale. `ProviderRegistry` applies a conservative preflight below every caller, including worker synthesis, and refuses over-budget work before the adapter executes. A cost-capped response must also contain valid bounded usage. Model events and the redacted run monitor expose estimated spend without exposing prompts. This is request-level protection, not a vendor invoice or a tenant-wide billing ledger; subscription CLI routes retain token budgets and reject invented dollar accounting.

Direct API adapters are the production path. Codex CLI and Claude Code CLI adapters are optional local transports for subscription-backed personal use. They are deliberately tool-disabled and ephemeral; the durable runtime remains the only action authority.

```text
CLI clients / channels / webhooks / schedules / ambient sources
                       |
 persistent daemon + connector registry + explicit plugin capabilities
                       |
                  event ledger
                       |
 attention gate + bounded inquiries + perception lab + personal-model projections + durable job queue + institutional office + work orders
                       |
   context assembly -> bounded agent run -> action policy
       |                     |                   |
  memory views         provider adapters     tools / MCP
       |                     |
 raw evidence       retained agents + goals + prepared work
```

## Composition and onboarding

The runtime is assembled from explicit, inspectable data before model work begins:

1. `onboard plan` resolves a neutral profile, explicit member phone principals, distribution, workspaces, per-role model routes, selected plugins, and optional execution policy without writing files or storing credentials.
2. `onboard apply` verifies the content-addressed plan and creates the profile with exclusive-write semantics; it never overwrites an existing profile.
3. `onboard verify` resolves the installed cell and reports provider credentials, plugin activation, execution policy, and production-safety issues.

Plugin discovery reads bounded `plugin.json` descriptors only. Selected plugin IDs must be unique and every contributed path must resolve within its package. Manifest v1 contributes skill roots, namespaced MCP descriptors, and optional sensor descriptors for calendar, email, call, file, browser, or location evidence. A sensor must identify an explicitly allowlisted, locally classified read-only MCP tool and declare its purpose, data classes, and retention window. At runtime that tool is wrapped by the consent manager before registration: the current descriptor hash must have a tenant-scoped grant or execution fails before the provider is called. Any descriptor change makes the grant stale. Connector adapters and execution backends use typed registries in core and can become later manifest contribution types without changing the ledger or run model. Plugin packages are trusted operator-installed inputs, while content returned by their tools remains evidence subject to the normal trust and authority rules.

The connector registry translates authenticated transport input into a primary receipt event, optional evidence/route events, and an optional normalized inbound message. A webhook signature authenticates the provider, not the person: human-authored Sendblue/Linq ingress must additionally resolve to an operator-supplied canonical direct phone principal before raw payload, route, evidence, or work is retained. Unknown senders, unbound human events, and groups leave only a content-free hashed rejection receipt; the worker repeats the principal check before executing a connector turn or approval. Delivery-status callbacks remain admissible only as provider evidence causally bound to an existing outbound message. Workers deliver only through a registered adapter that declares outbound readiness. Sendblue and Linq are rails, not branches in the reasoning loop. Authorized direct traffic from the same phone is stored in one `imessage` relationship session; the session separately records the current delivery rail, and Linq's phone↔chat projection is durable and tenant-scoped. Rail changes therefore do not fork memory, while replies, background results, approvals, recovery notices, and proactive messages still use the carrier that most recently reached the member.

Member connector turns carry the exact `connector.member_ingress_authorized` event into the canonical `message.received` causation link; reusing a provider message ID with another authorization fails closed. `ConnectorRoundTripQualifier` walks that immutable chain through the release-pinned run, recomputes the outbound reply digest, requires provider acceptance, and then binds a delivered/read projection to its authenticated status callback. It is a read-only deployment gate: it cannot manufacture missing evidence through retries or operator reconciliation, and it emits only identifiers and hashes rather than message or webhook content. Status callbacks that race ahead of local acceptance qualify only through the explicit reconciliation bridge.

## Donor systems

- **Donna:** a witness with continuity; stable self + retrieved episode split; explicit uncertainty; natural use of context; corrections; tact and timing.
- **OpenClaw:** channels as adapters, pairing/allowlists, a local gateway, daemon ergonomics, skill loading, sandbox/tool policy, streaming, and operational completeness.
- **Hermes Agent:** broad model routing, rich tools, bounded delegation, durable boards/jobs, approval and checkpoint concepts, middleware/observers, and migration-friendly profiles.
- **Nurk:** append-only ledger, rebuildable projections, attention budgets, consent, scoped memory, change-triggered dataflow, and citations.
- **Pi:** a compact, model-agnostic turn kernel. It can be used through an adapter, but is deliberately below the durable runtime boundary.

## Memory: evidence first, graph second

The append-only event ledger is canonical. Memory rows are projections with source event IDs, confidence, validity windows, and correction chains. The relational personal-model projection adds explicit thought, concept, source, and latent-thesis nodes; evidence links; thesis/concept edges; and correction-preserving source-affinity signals. Source nodes aggregate by author when known and otherwise by publication domain, with every artifact URL retained as an alias. Sharing creates a zero-weight attention signal, never an endorsement. A future Neo4j/Graphiti adapter may make traversal better, but it must rebuild from the same events and projection evidence; a graph database is not the source of truth.

Schema version 55 preserves enough provenance for reconstruction, migrates in place, and can be backed up online. Versions 11–55 add perception hypotheses, supporting/contradicting evidence links, explicit feedback, lossless corrupt-run quarantine, inspectable corrupt-record quarantine, lease-fenced semantic effect receipts with explicit reconciliation state, transport-independent relationship routing, durable connector routes and reconciliation history, deadline-backed promises, evidence-backed personal-model graph/source-affinity projections, provenance-bound WorldScout research records, reversible consequence plans, receipt-bound fail-safe persistent read scouts, quiet source-health/watermark and event-wakeup state, opaque workspace-bound credential records, bounded standing-authority use claims, descriptor-bound progressive sensor consent and retention expiry, integrity-checked portable tenant lifecycle state, immutable behavior-release and skill snapshots, admission-pinned durable jobs, immutable artifact versions, owner-provenanced product-outcome measurement, bounded proactive-delivery retry state, principal-typed synthetic instructions, delivery-time attention reservations, prepared-consequence work-order links, explicit intervention urgency, durable relationship-level delivery admission, content-addressed inbound originals, and bounded backstage inquiries with separately audited foreground decisions without rewriting earlier email, work-order, office, artifact, or source records. Historical evidence, its full-text index, and the personal model have concrete rebuild commands; history reindex preserves all provenance-bearing evidence and reconstructs only disposable search state. Memory, perception, inquiries, research, consequence plans, scout state, and consent views remain correction-preserving projections rather than sources of truth. “Canonical” describes the ownership rule, not a claim that every current SQLite table already has a finished reducer.

Context is assembled by type rather than by a single recency-ranked search:

1. **Carried:** a small, user-confirmed/stable portrait and live constraints. This is not top-k retrieval.
2. **Retrieved:** query-relevant facts, relationships, prior decisions, and episodes. Confirmed memory uses lexical overlap, salience, confidence, and weak type-dependent freshness. Dated raw excerpts use local full-text search with a per-month cap so a dense recent period cannot consume the entire context window.
3. **Recent:** a bounded verbatim conversational window.
4. **Ambient:** current time, location precision, calendar state, and active work, each with freshness and provenance.

Recency is a weak tie-breaker, never the main relevance score. Contradicted memories become historical; they are not silently deleted.

## Institutional service without accountability pressure

The office layer separates service from goals. An operator-approved mandate describes standing service and delivery boundaries; a proposed mandate grants no authority. A matter represents an evolving situation and links to immutable event evidence. Prepared artifacts hold useful drafts, briefs, research, or plans before an interruption is justified. Attention items hold relevant context with an explicit reason and delivery mode. A promise is Co's own accepted future burden—not the member's goal—and is persisted with its deadline job before the model may acknowledge it. Linked work settles it only from receipt-backed completion; an overdue promise remains in history, creates a repair item, and surfaces an honest miss through the current relationship rail.

The `today` view is a compact projection over those records, pending approvals/jobs, and near-term calendar evidence. It does not invoke a model. `why` resolves a service record back to source events and lifecycle events. Useful attention that cannot or should not be delivered is held; low-value signals remain silent. Lifecycle transitions update projections and append events rather than deleting their earlier state.

`WorldScout` is an evidence contract above the ordinary work-order engine, not a second agent loop or a hardcoded search vendor. A commission snapshots the read-only external research tools available to its originating run and binds to one durable work order. Each source record must point to a successful outcome-scoped receipt from that exact run. To claim strong coverage, the retrieval adapter—not the model—must emit a reserved versioned evidence envelope with canonical URL, title, publisher, source class, coverage, completeness, and a SHA-256 digest of the exact returned content; all model-supplied fields must match it. Final findings require independently published, fully inspected sources, a configured primary-source count, and explicit mapping, limitations, counterevidence, and changed implication. Search snippets, metadata, truncated reads, model-self-attested provenance, same-domain padding, forged URLs, and familiarity-only evidence cannot satisfy completion. Commission, source, and finding events preserve provenance; the tables are correction-preserving projections and are not allowed to rewrite the evidence ledger.

Accepted research, perception, ambient, and artifact assessments can enter a separate consequence planner. That planner receives no tools. Its closed output vocabulary can only discard, hold context, create a watching matter, or prepare a private artifact such as a brief, draft, research note, reminder option, scheduling option, outreach option, or action option. A local confidence/usefulness/novelty and knownness gate can override the model to discard. No consequence plan can encode sending, purchasing, publishing, booking, or contacting; those effects still require the ordinary tool policy, approval/mandate boundary, and semantic receipt.

A prepared consequence can become executable only from a current owner-authored message containing a verified verbatim request to proceed. `consequence.work.submit` binds it to one idempotent work order whose tools cannot exceed the foreground run's authority. The work order then crosses ordinary approval or mandate checks and names the exact semantic receipts required for completion. Consequence status follows queued, approval, failure, and verified-completion states without erasing the original private artifact or rationale.

A persistent scout is a durable, read-only schedule over one snapshotted tool name, validated argument object, and creation-time behavior release. Its wake policy is `poll`, `event`, or `hybrid`; event hints never stand in for evidence. The authenticated wake boundary retains only a digest of optional hint payload, writes an immutable source event, advances a monotonic ledger watermark and opaque provider cursor, and makes the same receipt-bound snapshot read due. Bursts collapse into one pending generation. A hint that lands during a read remains above that run's captured generation and causes exactly one catch-up snapshot after completion. Event-only sources still take an initial baseline but do not poll after it unless woken. Poll recovery uses the same durable `next_run_at`; missed intervals skip forward rather than flooding.

The read tool must have read risk and be either a selected MCP contribution or explicitly tagged `scout-source`. Each admitted snapshot is an ordinary release-pinned work order whose authority contains only that read and `scout.observation.record`. The record call must come from the exact bound run, cite the exact successful non-truncated read receipt, and match the snapshotted arguments. The runtime—not the model—fingerprints canonical output. Changed output becomes untrusted ambient evidence and queues one background evaluation; unchanged output establishes a successful quiet read without creating a signal. Health is derived from explicit freshness, attempt, success, failure, cursor, and watermark state. Expired watches stop silently and retain history. Three consecutive failed or needs-input snapshots atomically enter `repair_required`, stop admission, append a causal event, and create one held operator repair item—not a member message. Preserved legacy scouts with no release binding also fail closed in `repair_required` until an authenticated operator names an existing assigned release. Resume acknowledges the repair and resets the bounded failure window; prior runs, observations, failures, and attention history remain intact. A source changing can wake bounded work, but never earns foreground delivery by itself.

## Tact and insight

Tact is an execution policy, not a warmer personality prompt. Every intervention is judged on evidence, novelty, usefulness, urgency, timing, reversibility, and interruption cost. The correct output is often silence.

Every bundled distribution keeps these distinctions explicit in context:

- observation: directly supported by evidence;
- inference: plausible but uncertain;
- proposal: what to do next;
- action: what the runtime actually did, with a receipt.

Praise requires evidence. Disagreement requires reasons. The runtime does not turn every conversation into self-improvement or accountability, and it never invents a psychological read to sound perceptive.

Product feedback is captured from ordinary conversation rather than a compulsory rating flow. `outcome.feedback.record` can bind only the current owner-authored message to the immediately preceding substantive assistant output in the same session, and requires a verbatim quote present in that message. The model cannot select a flattering historical target, use its own event as the source, infer approval from silence, or assert context advantage without a second owner quote. Canonical owner-event time—not later extraction time—drives longitudinal buckets. A rating counts as proactive only through the exact assistant message → acceptance event → accepted outbound intent → intervention chain; event naming alone is insufficient. Accepted and member-delivered volumes, coverage, positive/negative ratings, and message counts remain separate per tenure month. The append-only record drives aggregate reporting, but sparse coverage remains visible and no descriptive trend automatically closes the live product gate.

An inquiry is distinct from both memory and perception. It is a bounded uncertainty admitted only for a stated member benefit. The durable record carries competing hypotheses, falsifiers, answerability, retrieval steps, a step limit, stop condition, expiry, findings, counterevidence, remaining uncertainty, and the next permitted consequence. Creation defaults to `backstage` and has no delivery capability. Asking or surfacing is a separate append-only judgment: low member delta fails closed, member-answerable work must first be unavailable from authorized private/public evidence, an opportunistic question needs a real relationship opening, and interruption requires material value loss from waiting. This decision is still only an input to the one relationship arbiter, never a bypass around it.

Personal perception is distinct from memory. Memory stores sourced claims and episodes; perception stores explicitly tentative interpretations that may mature, be surfaced, be confirmed, or be rejected. Each foreground turn only queues synthesis, and the queue ranks perception behind every ordinary due job. A deterministic change gate requires longitudinal evidence, ignores tiny conversational changes, and coalesces ordinary conversation before model work. An inquiry planner first rejects curiosity without a concrete member delta or records the bounded question backstage. A background generator then receives that inquiry plus a bounded sample of owner evidence spread across months, related external-world evidence, prior hypotheses, and explicit feedback. It may emit at most two candidates. A separate counterevidence planner formulates a falsifying query; the runtime performs a new tenant-scoped, time-bounded retrieval that excludes the generator's initial bundle; and a verifier may cite only event IDs in those two bounded sets. An adversarial critic alone accepts and scores the claim; only then does a relationship composer compare a possible surface against the best quiet alternative and the member-delta gate. None of the model passes may use tools, and evidence dated after the trigger cannot enter their ordinary history bundles.

A hypothesis becomes `ready` only with at least three supporting events, two owner events separated by at least seven days, calibrated confidence/specificity/novelty/perceptual-value floors, low genericity, a plausible alternative explanation, and bounded contradiction. Ready does not mean delivered: perceptual attention has its own stricter score and begins with a zero-call local comparison against owner evidence and prior deliveries. If that comparison remains uncertain, a no-tools critic performs one bounded semantic and polarity comparison against exact allowed evidence; a claimed restatement or contradiction requires one of those event IDs. The same verifier now covers otherwise-eligible operational media/ambient candidates, optional substantive foreground observations, and reactivated holds. Explicit requests, tool-bearing runs, short acknowledgments, tapbacks, silence, local-known output, and weak operational candidates do not pay for it. Attention still obeys quiet hours, cooldown, daily budget, sensitivity, and interruption cost. Immediately before proactive dispatch, the worker resolves the current canonical relationship and yields nonurgent interventions for fifteen minutes when a newer owner message shows the relationship is active; the hold releases its daily reservation and is revalidated before later admission. Urgent operational notices may continue. Schema v51 adds the durable relationship-admission projection. Every current relationship send now crosses it with an explicit delivery class, immutable authority/content/transport binding, current canonical rail, lease heartbeat, delayed revalidation, exact transport settlement, and one owned repair item after retry exhaustion. Delivery changes the hypothesis to `surfaced`; only explicit feedback can confirm or reject it. Silence is never positive evidence.

This lifecycle is intentionally additive. Hypotheses link to immutable event IDs, corrections append feedback records, critic rejections append audit events, and the original conversations, imported logs, media artifacts, memories, and evidence rows remain intact. A graph database may later project relationships among these records, but it is not needed for the core correctness boundary and would remain rebuildable from SQLite history.

## Autonomy

Authority is structural:

- read-only and local-reversible work can run automatically;
- private drafts and internal memory proposals can run automatically and remain inspectable;
- external communication, financial actions, permission changes, destructive operations, and public commitments pause for approval unless the user granted a narrow standing rule;
- every tool call is atomically claimed by the current run lease, emits a durable semantic receipt (`succeeded`, `failed`, or `uncertain`), and has a stable tenant/work-order/run/call identity; external connectors propagate that identity where their APIs support idempotency and otherwise stop for reconciliation after an ambiguous outcome.

Per-call approval can be replaced only by a currently active version-1 mandate rule that names the exact tool, recursively constrains at least one argument, caps its own use count, and may expire. The runtime claims each allowance transactionally by tenant, mandate, run, tool call, rule index, and a hash of all arguments immediately before the ordinary effect boundary. It never stores a second copy of possibly sensitive arguments. Reusing a call identity with changed arguments fails closed. Pausing or retiring the mandate makes even an earlier unexecuted claim ineligible on recovery. Legacy descriptive authority JSON grants nothing.

## Action proof

A work order is the product-level action contract above a model run. Admission records an objective, success contract, evidence policy, source conversation, model role, token budget, and a sorted snapshot of allowed tools, then queues execution transactionally. The model cannot widen that snapshot, and `work.submit` is removed from child authority to prevent recursive work-order expansion.

The worker creates or recovers the ordinary durable run and binds its ID to the work order before provider execution begins, so session/run leases, tool validation, approvals, receipts, cancellation, and late-result fencing remain one mechanism rather than a second agent loop. The independent work-order projection then checks one of three completion gates:

- `run`: a completed run is the deliverable, while external claims still require their ordinary receipts;
- `tool`: the configured minimum number of named, outcome-scoped tool receipts succeeded;
- `external-write`: the configured named external-write receipts succeeded.

Tool-bearing orders must name their evidence tools. Required tools must already be inside the authority snapshot, are forced into the bounded model tool set, and cannot be satisfied by a read, unrelated preparatory activity, an accepted request, failed subprocess, or rejected delegation. A run that finishes without the required evidence becomes `needs_input`. It is inspectable and preserved, but is not called complete. Connector-originated orders return approval requests and final results to the exact originating channel/peer; approval replies are accepted only from that linked relationship. API and CLI admission are asynchronous, idempotent, and expose stable work-order handles. CLI status attachment tolerates bounded transient daemon failures without losing the durable handle.

## Reliability and trust boundaries

- Inbound receipts, their event, the user message, run creation, and queued enrichment work commit transactionally. Connector attachments cross this boundary as a bounded typed manifest whose digest is pinned into member-ingress authorization; the exact URL stays in tenant state while only an opaque kind/name marker enters the foreground prompt.
- A renewable session lease serializes conversation state across gateway processes.
- Runs and jobs have independent renewable leases. Every state commit carries the lease token, so an expired worker is fenced after another worker takes ownership.
- Tool receipts are the external-action recovery boundary: claims are atomic to one live lease epoch, semantic failure is not inferred from exceptions alone, and uncertain or prior failed calls are never repeated automatically.
- Dependency adapters classify retryable, permanent, rate-limited, and uncertain failures. Retryable provider work resumes the same durable run. Definitively rejected proactive delivery uses persisted exponential backoff with a fixed attempt ceiling; ambiguous delivery creates a held reconciliation item instead of a duplicate send.
- URL fetches connect to the public IP that was validated, revalidate every redirect, and bound time and bytes.
- Imported logs, web pages, transcripts, and connector payloads are evidence, never instructions. Provider tools are disabled during background interpretation.
- Historical excerpts have explicit owner/agent/untrusted provenance. Automatic context excludes untrusted material; deliberate history search can include it. Every excerpt is source-linked and prompt-fenced as quoted data.
- The runtime process is still one operator/tenant trust boundary. Tenant IDs prevent accidental cross-tenant reads, but hostile users require separate processes and OS/container isolation.

## Collaboration

Retained agents are bounded collaborators, not free-floating personas. Each has a stable tenant-scoped ID and session plus an objective, deliverable, allowed tools, model role, token budget, depth, parent, bounded mailbox, lifecycle state, and event stream. Admission transactionally creates the agent, objective message, and queued job, then returns stable handles immediately. The job queue enforces execution concurrency without dropping admitted work.

Each mailbox turn reuses the retained agent's session. Owner and family-scoped messages can steer or follow up after an earlier turn; cancellation and retirement stop future work but preserve messages, runs, events, results, and artifacts. There is no transport-level preemption of an already in-flight provider or tool request, but cancellation fences the run before any late model result can become output or authorize another tool call. An external effect already in flight remains represented by its receipt.

The agent monitor derives parent-child run trees and retained-agent views from durable runs, messages, receipts, approvals, and events. It exposes bounded, secret-redacted objectives, mailbox previews, and output previews plus operational counters. It intentionally omits system prompts, provider reasoning blocks, tool arguments, and unbounded tool output, so observability does not become a hidden-state exfiltration endpoint.

Persistent goals hold an objective, explicit success contract, evidence gate, deadline, token budget, and continuation budget outside any one context window. Current deterministic gates check manual confirmation, event counts, artifacts, or run completion. Failed checks are keyed to the evaluated evidence hash; unchanged failures are reused, while changed evidence can wake a bounded follow-up on the assigned retained agent.

An owner-quoted goal becomes an accountability surface only when it is linked to an active, separately approved standards mandate. For those goals, `GoalManager` may hold one private motive hypothesis as interpreted state: a release-pinned background generator proposes it from temporally bounded owner evidence, a separate critic must accept it, and persistence enforces a strongest alternative, falsifier, literal evidence cues, and a 0.65 confidence ceiling. The same row may hold one optional substitution candidate with independent evidence, alternative, falsifier, cues, and a lower 0.55 ceiling. Its evidence must be a subset of the motive's cited owner record, include the triggering decision, and span at least seven days.

For countable event goals that explicitly configure `referenceWindowDays`, `GoalManager` also derives bounded historical windows entirely from pre-commitment canonical events. Conversation-created goals must state that exact horizon in the verified owner quote, so a model cannot silently choose a favorable comparison period. Only windows exceeding the stated target become candidates. A private motive may bind one stable candidate when its cited owner evidence includes both context inside that window and the current trigger; the binding has an independent alternative, falsifier, and 0.50 ceiling. The foreground tool receives a sanitized arithmetic projection and cannot choose or alter its event IDs, dates, duration, or count. Neither private interpretation enters foreground context or a member-facing tool. Their cues only gate when the ordinary quoted commitment and deterministic arithmetic check are available. `OutcomeLearner` can retire the exact hypothesis only when verified negative member feedback traces through the exact delivered check; superseded and rejected versions stay append-only and cannot silently reactivate.

Attach/resume is a control-plane view over durable state, not ownership of the worker process. The CLI first verifies that a daemon serves the same tenant, gives each submitted turn an external ID, then follows its ingress receipt and run cursor. CLI and HTTP clients can request bounded runtime, retained-agent, run, or goal snapshots plus events after a sequence cursor. SSE honors `Last-Event-ID`, so disconnecting does not cancel work or require replaying the full history. Explicit cancellation denies pending approval and releases the run lease while retaining durable state; late provider or tool completion remains fenced by the existing run-status and receipt boundaries.

Private longitudinal replay is a release-qualification boundary, not runtime memory. Corpus preparation creates a new permission-restricted file and refuses to reinterpret timezone-less source timestamps without an operator-supplied offset. The source hash proves preparation did not rewrite the raw log. A versioned external packet binds each harness case to the exact pre-checkpoint history and checkpoint. The capture path invokes an operator-selected external runner over JSON stdin without a shell, hashes its executable, fixed arguments and regular-file argument contents, and configuration, and binds those plus the case input, response, and receipts into baseline schema v2. The shipped OpenClaw adapter exercises the real `agent exec` interface against isolated state while pinning the clean source commit, executable, invoked source, generated runtime, dependency metadata, and OpenClaw configuration before and after every case. It provides prior conversation as quoted JSON evidence; it does not pretend to recreate native OpenClaw session state. Generic tool-call summaries never become semantic receipts. Post-capture replacement then fails before a private model call. The full-context and history-withheld variants execute the same Co release, tools, and semantic receipt path in separate cells, so context contribution is not confounded with tool access. Confirmed semantic receipt requirements are applied symmetrically to all five blind variants. Ordinary reports redact both responses and free-text judge rationales, retaining hashes for audit, because either may repeat private transcript content.

Product metrics and product qualification are separate surfaces. Metrics retain canonical conversational feedback as directional evidence. Schema v52 adds tenant-scoped preregistration, commit/reveal deterministic stratified sampling over all terminal relationship decisions plus legitimate silence, blind packet export, append-only external-human reviews/corrections, disagreement adjudication, and one-sided Wilson bounds. Frozen review state participates in verified tenant export/restore and exact-confirmation deletion. `MemberProductQualifier` version 2 treats first-wow, feedback ratios, context advantage, and tenure as diagnostics; none can make a release pass. Required stages are projection sufficiency, promise reliability, action truth, exact rolling-24-hour interruption limits, and a qualified same-tenant representative live review plan. Missing, synthetic, sparse, incomplete, unknown, mismatched, or internally corrupt review evidence fails closed. Reviewer humanity/independence and cross-tenant cohort aggregation remain externally governed rather than self-attested by the runtime.

## Governed adaptation

Self-improvement is a reviewable data lifecycle, not autonomous prompt mutation. The existing learned-skill lifecycle remains, and a model may now propose typed prompt overlays, agent specifications, procedures, or memory-policy changes with source evidence, rationale, predicted effect, scope, and planning baseline. The model-facing tool can only propose. Operator-only surfaces approve, reject, apply, retire, or roll back a proposal.

Application uses optimistic version checks and creates an immutable overlay version. Supersession and retirement change active state without deleting old records; rollback restores reviewed content as another new version. Only approved prompt overlays are currently consumed by model prompts. The other proposal kinds are deliberately inert until a separately governed consumer exists.

Skills and refinements never carry authority. Patch validation rejects action risk, standing approvals, connector permissions, provider credentials, secrets, and workspace roots. Proposal, review, application, supersession, rollback, and retirement are all durable events.

## Execution isolation

`process.run` is not registered when the execution backend is `none`. Enabled calls use no shell, an exact executable allowlist, a realpath-contained workspace, bounded arguments/stdin/output/time, and a secret-minimized environment. The local backend exists for development and is rejected by production validation.

The Docker backend additionally uses a digest-pinned image in production, disables network access and daemon logging, mounts a read-only container root, drops capabilities, enables `no-new-privileges`, limits PIDs/memory/CPU, uses a no-exec temporary filesystem, adopts the host's unprivileged UID/GID, and mounts only the workspace selected for that call with the configured read-only/read-write mode. Every sandbox is named and labeled. Timeout or output overflow kills the attached client, forcibly removes the named container, and verifies cleanup; an unconfirmed cleanup becomes a failed non-idempotent receipt. The runtime still classifies every process call as destructive-risk and requires explicit approval under production-safe authority defaults.

## Browser credential boundary

Credential storage is an operator subsystem below the model. AES-256-GCM additional authenticated data binds each ciphertext to its tenant, browser workspace, credential ID, and normalized exact origin. Management surfaces return only an opaque handle, label, origin, field names, status, and timestamps; events and evidence never contain values or ciphertext. Retirement is append-only and prevents future fills without deleting the historical record.

`browser.credential.fill` is an ordinary non-idempotent external-write tool, so it pauses at the same argument-bound approval gate as other consequential effects. Its arguments contain a handle, existing CDP page target ID, and selectors keyed only by field names present on the handle. The broker checks the current target origin, decrypts immediately before use, and the CDP expression rechecks `location.origin` before touching the document. Discovery accepts HTTPS or loopback HTTP only and rejects a websocket target that leaves the configured host, port, or transport boundary. The injected script uses native input setters and events, marks every filled field, and installs a screenshot mask before returning a receipt. It does not submit the form. Plaintext is cleared from mutable buffers and temporary field maps where JavaScript permits, and it is never returned to the model or durable state. The destination page necessarily receives it; compromised browser/page code remains outside this claim and requires deployment isolation.

## Media eyes

Media ingestion is a background dataflow, not part of the foreground model call:

```text
shared URL -> idempotent durable job -> typed, bounded source inspection
                                              |          |          |
                                              v          v          v
                                      exact captions  text/README  native media
                                              \          |          /
                                               -> versioned tenant artifact
                                                            |
                                                untrusted evidence +
                                                usefulness/consequence gates
```

`VideoAnalyzer` is the provider-neutral media boundary. The Gemini implementation sends public YouTube URLs directly for audio/visual understanding and accepts bounded inline document, image, and audio resources. It uses low media resolution and adaptive frame sampling, and bounds oversized video work into temporal windows. `yt-dlp` remains the exact-caption and metadata rail. Ordinary HTML is retained as bounded visible text; direct textual resources remain text; direct audio, images, and supported documents use native analysis when configured; GitHub root URLs fetch repository metadata plus README. Unsupported binaries remain metadata-only. Content work never stalls the conversation thread.

The foreground/binary boundary is explicit: signed connector capability URLs are dereferenced only by the backstage job. Model-facing source labels strip query strings and fragments, including in enrichment repair notices. Exact text, the raw authenticated webhook, attachment descriptors, and source references remain immutable. The first successful bounded attachment fetch is stored by SHA-256 in tenant-scoped `original_blobs`; `original_blob_refs` retains each distinct source-event/attachment binding. Bytes are captured before interpretation, so partial or unavailable analysis does not erase a fetched original, and preservation does not inflate the coverage label. Both tables participate in portable export/restore/deletion and online SQLite backup. A URL can still expire before the asynchronous first fetch; multi-host deployment must replace the SQLite base64 reference implementation with a transactional object-store adapter.

Coverage is explicit (`metadata`, `fulltext`, `transcript`, `multimodal`, `transcript+multimodal`, `document`, or `repository-overview`) and downstream prompts may not claim more than it establishes. DNS-pinned resource retrieval revalidates every redirect and bounds bytes before analyzer admission. Artifact versions are immutable events while the artifact table remains a latest-value projection, so refresh does not erase older evidence. All source content is untrusted evidence. Neither the native analyzer nor the background usefulness pass receives tools.

## Scaling

SQLite is the local-first reference store. Ledger, jobs, memory, providers, tools, and channels are separate logical modules, and provider/tool boundaries already have explicit interfaces. Multiple processes on one host coordinate through SQLite transactions and leases. Deployment across hosts requires a transactional Postgres/queue/blob adapter rather than merely changing configuration. Tenant IDs scope every row and the daemon processes only its configured tenant, but hostile tenants should still receive separate gateway/container cells; hosted authentication and secret isolation remain future work.

Tenant portability discovers every current table carrying `tenant_id` rather than maintaining an incomplete hand-written list. A consistent transaction produces a canonical digest of the complete tenant state and a v3 JSON export containing the exact global behavior-release manifest/rollout dependency closure. Browser credential ciphertext, IVs, and authentication tags are omitted. Audit exposes counts and digests, not content. Local restore requires `RESTORE:<tenant>`, an empty destination tenant, the current schema, and nonconflicting global dependencies; it imports atomically, remaps only SQLite-local event sequence numbers, reconstructs full-text search, and reports credential handles that need re-entry. Explicit deletion requires that exact current-state export and `DELETE:<tenant>` confirmation, enables SQLite secure deletion, removes only matching rows, truncates the WAL, preserves a tenant-hashed lifecycle receipt, and never follows or edits imported source paths. Restore and deletion are operator rights; no model or HTTP mutation can invoke them. Deletion is the sole intentional exception to normal append-only retention.

Behavior releases are complete immutable manifests, not mutable flags. Each manifest fixes the distribution prompt, all four model routes, exact skill versions, and requested auto-approval risks under a content digest. A rollout has one stable release, at most one canary, a random cohort salt, and a basis-point allocation; the tenant assignment is deterministic and persisted for that rollout. Every admitted run stores its release, digest, rollout, and cohort, while its resumable state pins the actual prompt, model route, and effective policy. Durable background jobs are also pinned before execution, and derived work inherits the originating run's release, so a rollout change cannot split one causal chain across behaviors. Promotion and rollback atomically replace the active rollout and append an operator-visible event. New rollouts affect only newly admitted work. Stored-manifest tampering and missing skill versions fail before a provider call. Manifest policy is intersected with the deployment's configured auto-approval risks, so a database rollout cannot widen action authority.
